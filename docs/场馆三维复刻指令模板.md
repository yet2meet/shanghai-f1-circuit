# 场馆三维复刻 · 指令模板

复制下方**指令正文**整块，最少填写**场馆名称、项目情况和本次范围**。赛事日期、参考图片和交付方式有要求时一并填写。正文内含执行顺序和验收标准，可直接交给一个不了解本项目的助手使用。

本模板从上海国际赛车场和新加坡滨海湾街道赛道的实现与验收整理而来。固定赛车场、街道赛、足球场、篮球馆等场馆共用同一套资料核对、比例建模和验收流程，再按场馆类型选用相应条目。

## 指令正文

~~~markdown
请为我做【场馆名称】（【城市 / 国家】）的三维网页复刻，或按我指定的范围维护现有模型。回复和验收记录用中文。

## 1. 任务输入

- 场馆类型【街道赛 / 固定赛车场 / 足球场 / 篮球馆 / 其他，同一场馆可多选】
- 项目情况【新建 / 在现有项目新增场馆 / 维护现有场馆 / 只核查】。现有项目路径【路径】；新建网页可用 Vite + Three.js。
- 时间基准【赛事、赛季或场馆版本，包含日期和当地时间（若有）】
- 本次范围【主要建筑、比赛区域、看台、地标、周边道路、室内区域或问题截图】。例如“只查新加坡的道路接续和穿模”，范围就是整个新加坡路网及与它相交的场馆地物。
- 参考资料【官方平面图、座位图、实景照片、转播截图、坐标、想对齐的现有场景（按需填写）】
- 交付方式【本地预览 / 完成并推送 / 仅报告核查结果】。默认给出本地预览。发布目标沿用现有项目设置。
- 可选功能【选座、座位视角、票价、日夜、卫星图、双语、分享、比赛动效】。维护已有项目时沿用已启用的功能。

## 2. 先确认范围和基线

1. 阅读仓库说明、现有场馆入口、模型和数据生成脚本。确认检出版本、未提交修改、运行命令和项目发布方式。
2. “先别改”“只核查”只执行定位、测量、源码阅读和本地预览。按任务检查模型、使用流程、性能和代码可靠性。报告复现机位、原因、代码位置、影响及实测结果，并列出待处理范围。
3. 对截图先辨认场馆、弯号或地标、视角方向、画面中的前后关系和用户圈选范围。区分现有缺陷、截图透视、时段差异与用户明确保留的行为。
4. 新建或大改先给场地、看台、主要桥梁和建筑建立比例基准。维护先从同机位复现旧问题。先确认位置、标高、净空和范围，再加材质、灯光与细节。
5. 用户纠正后更新当前要求。把纠正后的约束应用到范围内同类对象。用户指定只改一区或只发布某一版时，保持其他本地工作独立。资料足够就继续；场馆身份、赛事版本或改动范围确实无法判断时，再提出一个具体问题。

## 3. 资料和精度

- **资料优先级**按问题选来源。平面和动线优先用官方场馆图、赛事图、测绘数据和 OpenStreetMap（OSM）；层数、容量、赛程、票价、车库分配用对应年份的官方文件；造型、材质、布灯和细部用同一时期有明确拍摄位置的照片、转播或建筑资料。针对宽度、高度等关键数据交叉核对。
- **建立基准**统一米制比例、当地坐标、真北、地面基准与正方向。记录比赛方向或主客队方向。核对场地长度、跨度、弯数、场地边界、看台侧别和地标朝向。固定赛事版本，先确定临时设施属于哪一年。检查 OSM 的 `height`、`min_height`、`building:part`、`bridge`、`layer`、`tunnel` 和地块内洞；平面相交处要重新判断垂直关系。
- **按实测比例建模**有可靠数据的尺寸和位置按真实比例；照片只支持比例判断时记录估测依据。位置可确认、细部尺寸缺失的部分，可在任务允许时做明确标注的示意模型。容量、通道位置、灯杆、广告、地下或室内构造等缺乏证据时，只做资料支持的部分；说明缺少的视角或图纸。示意尺寸与排座数量单独标明，真实容量有可靠资料时按看台与票区分别核对。
- **保留来源**为每个关键地物记录对象、来源链接、年份或资料版本、对应数据或文件、实测或示意、可见限制。关键尺寸与推定依据写进相应数据或源码注释。界面及 README 说明模型精度；照片、数据、字体、商标、模型和纹理沿用其各自许可。在已确认的名称和位置使用赛事文字。用图形商标或外部素材前核验授权；缺少许可时使用文字或原创替代。关于页注明独立爱好者项目及素材归属。
- 票价按收录时的官方页面记录赛事年份、票种、币种、税费口径和资料日期。历史票价标为对应年份，实时库存只有接入可靠数据时才展示。票区、入口和通行权限依据相应赛事资料。界面把模型排号、座号、估算容量与官方信息明确区分。

## 4. 所有场馆的基础建模

### 4.1 场地、建筑和地面

- 先做场地边界、路网或人行路线、入口、看台、建筑和地面标高，再补栏杆、设备、灯光和人员。相邻区域共用投影、地面和测量基线。核对岸线、水面、地块、坡地、地下通道口以及桥下地带。
- 建筑要对齐批次时段内的真实轮廓、层高、屋面、立面分区和入口朝向。先做好远景轮廓和色块，再做门窗、混凝土、玻璃、金属及铺装的近看尺度。架空结构与屋顶具备可见的支撑、底面和厚度。玻璃透明区域与实体结构有明确边界，避免漏光、闪烁、面翻转和墙体悬空。
- 地面铺装和建筑入口尽量沿资料给出的路径衔接。缺少细节的地块以完整的简化体量、铺装或绿地交付。临时施工元素只在当前场景明确要求还原该状态时制作。
- 需要细化室内时，按真实功能安排设备、屏幕、人员、通道和光源。场内外人员落在可行走或可站立的区域，规模与场景用途相符。远景简化室内陈设，近景保留设备尺度和使用关系。

### 4.2 看台、进出口、座位和视线

- 弧形与折转看台沿真实平面线整体扫掠。采用连续踏面、竖直踢面和随标高变化的后墙或端面。每排按各自弧长放座位，径向过道共用左右边界。近看检查每排踏面、座位底座和端墙，避免从上到下斜成一整块。直线段、内弧或分段看台按实景处理，检查尖角、自交和扭曲。
- 依据真实看台和座位图划分层、区、排与走道。上层首排与下层末排、平台和层间通道要衔接。相邻过道与座席按同一份排布数据生成。缺少精确出口平面时，按场馆类型与照片设置可解释的示意动线，并标注精度。
- **进出口是可读的实体通道口**。保留开口、平台和上、下过道的连接；两侧踏步与同排座席踏面对齐。洞口内保留走行空间，座位、连续阶梯或护栏都不能把洞口封住。检查从场内回看、沿过道走向看和斜侧看三个方向。
- **按上海和新加坡当前样式制作的出入口**，左侧、右侧和高侧各一块平整的实心护板，三块接成水平顶边的 U 型，低侧留开口。两侧护板之间保留通道净宽，两侧台阶正常衔接。高侧实心板是一段局部防护，不占用下方走行净空。新加坡样式的每座看台都在顶部或背缘加连续护栏，通行开口按实际动线留出；其他场馆按证据与任务选用顶栏、玻璃栏板或实板。上层看台同样检查顶部护栏、上下通道和层间开口。
- 共用几何基准生成座位、通道、顶缘、标签、点击区域和座位视角。调整看台偏移、进深、座位排数或高度时，一并更新射线拾取、点击区域、视角和标签。低位视角核对栏杆、网、广告、顶棚遮挡与视线；预期遮挡按模型如实显示。
- **检查全部看台**。抽样看台只覆盖视觉细看，每种造型至少复查一座；穿模扫描要覆盖所有看台的前缘、后缘、顶栏、通道、上下层、挑檐和座位。发现相交时找出实际重叠的几何与净空。优先调整不准确的示意体量，在已有资料允许的范围内调整位置、进深或高度，继续保留选座与票区关系。

### 4.3 路网、高架与穿模

- 按原始道路拓扑组织地面道路、匝道、步道、隧道口和高架。使用 OSM 或可靠图纸中的共用节点、道路等级、方向与桥梁层级识别接续。短连接段也参与建模。相互靠近只表示空间距离，需要用拓扑和标高确认它们的实际关系。
- 同一路幅的接头统一标高、材质和纹理尺度，核对边缘截面、转向、宽度渐变、标线和护栏。护栏到岔口、跨缝或出入口要按动线收口。不同标高铺成连续坡道；上下交叉时量桥底和下层物体的净空。断头、裂缝、突然台阶、色带、错边、飘浮路面和盖住真实开口都算未完成。道路在真实尽头或场景裁切边缘停止时，应有与现状相符的衔接或明确的场景边界。
- 桥梁可用简化的箱梁、板梁或可验证轮廓，桥面、侧缘、底面、桥墩、引道和护栏仍要完整。路面与桥墩共用同一套高度函数或实际网格采样。坡度变化处细分路面，避免仅用两个端点插值后，桥墩按另一套高度从路面露出。外侧步道、栏杆与桥体要接实，外侧缝隙不能露出水面或空白底面。
- **全路网检查是逐条路段、逐个接头**。记录同层节点、分岔、跨路、跨水、立交、坡道与岸上接路。检查桥墩是否顶穿上层或落入下层道路、赛道、步道、看台；同时查树木、建筑、围栏、屋顶和地下入口。看台净空用桥底真实标高与看台顶缘、护栏和出入口比较。平面重叠但垂直分离的对象标明已核对净空。
- 实现允许用几何检查脚本扫描全量路幅、坡度、接头高差、桥底和支撑占位。浏览器补验斜侧、贴路面、桥底与两岸近景。高架改动后特别回看相邻匝道和全部受影响的看台，避免只修截图里的一个点。

### 4.4 地标与复杂造型

- 先核对主轮廓、尺度、方向、落地方式和容易辨认的构件，再补靠近镜头的细节。至少从正面、侧面、斜后方和场馆常用视角对照实景。单一角度重合的构件要用侧视和剖面确认。
- 摩天轮或类似大型机械构件按证据核对轮径、轿厢数、轮缘、轮毂、辐条和支撑。实际有双侧支撑时两侧各自接地并接到轮毂，从正侧视确认双腿和轴承的关系。检查底座、支撑与轮缘、轿厢没有穿插。
- 雕像要保留识别用轮廓与连续体量。鱼尾狮一类造型先对狮头、鼻口、鬃毛、鱼身、鳞片、尾部和台座，再校对喷泉高度与方向。喷水起点接嘴部、落点进入水体，检查闭合网格、法线和阴影。
- 复杂地标建筑先做独立主体与基座，再按实景组织屋面格构、折板、玻璃、格栅和夜景。滨海艺术中心一类双壳顶要分开核对两座体量、网格方向和裙房关系。细部共用材质与批次，避免近看像重复贴图、远看丢失主轮廓。

## 5. 按场馆类型套用

### 街道赛

- 按赛事年份核对中心线、弯序、护墙、路肩、起终点和临时设施。比赛道路与城市路网共用坐标，同层城市道路接到比赛路幅边缘，独立跨线结构保留证据支持的净空。检查城市道路、立交、人行桥、跨水桥、街道建筑、滨水地面和赛道护栏的交界。
- 参考新加坡场景时，以滨海桥的两岸接路、Sheares 高架匝道的连续铺面、Jubilee 步行桥的连续步道为验收案例。临时看台按该年场图定位，逐一和桥底、道路以及障碍物复核。
- 夜赛默认夜景时，先从全景确认赛道连续、与背景能分辨，再看路边和车库的明暗层次。根据资料决定加哪些灯具，局部补光作为示意可视化处理。

### 固定赛车场

- 先核对赛道布局版本、比赛方向、宽度、坡度、路肩、缓冲区、维修通道、进出口、起终点、发车格和看台视线。核对主看台层次、顶棚、维修楼、围场和范围内的交通。
- 对 8 字形赛道、赛道上下交叉、桥下视点、坡顶、落差和坡道坡脚增加验收。检查围栏、护墙、桥墩、缓冲区和比赛路线的相互位置。
- 参考上海场景时，用主看台上下层、翼形顶棚、各票区、维修楼、围场和场内卡丁车场作为不同建模层级的示例。线路、层高和票区按目标场馆资料重新核定。

### 赛车维修区（街道赛与固定赛车场通用）

- 先核对赛道、维修墙、快车道、车库侧工作区、换胎位和维修楼立面之间的关系。相应年份有官方维修通道图或车库分配时优先按它确定相对位置与车队顺序。宽度、比例或设施位置缺少资料时标为示意，并优先保证车道、车库出入口和步行可见空间连续。
- **工作区与换胎位**要有清楚的地面标线和车库对应关系。车队指挥台用于控制与遥测，按实景沿维修墙或指定工作位置布置。可参考上海已做的车库、指挥台、屏幕与工具精度，再按目标场馆路幅调整体量。
- 放置车队人员、技师、工程师和设备时保留走行线。检查快车道、换胎位、工作区、车库口和维修通道进出口。人员、轮胎、设备、观察台和隔离设施避免侵入车流线或穿过墙体。用俯视确认布局，用低位斜看确认车库和指挥台都能辨认。

### 足球场

- 确认联赛或比赛使用的场地尺寸与图示版本。先做草坪、边线、禁区、中圈、球门、球网、角旗和缓冲边界，再做看台碗、球员通道、替补席、技术区和设施。草坪条纹、标线厚度、座席颜色与分区按资料调整。
- 看台前缘与围栏、广告、球门后空间、入场通道保持合理净空。体量按真实屋盖跨度连接，检查立柱、悬挑、雨棚、照明与看台。按前排、后排、角区、顶棚下和无障碍区域检查视野。需要做转播、包厢或更衣室时，以场馆实际功能和本次范围为准。

### 篮球馆与其他室内场馆

- 核对联盟或赛事采用的场地尺寸、标线和主客朝向。篮球场核对木地板分区、篮架、篮板、篮网、计时装置、两侧替补席、记录台和缓冲区。分清固定座席、伸缩看台和临时地面席，以当前活动状态为准。
- 从场边低位、下层角区、上层中区、篮架后方及入口复看。检查篮架、吊屏、顶棚桁架、悬挂设备、楼层走道与观众视线。其他演出或多用途场馆按实际舞台或场芯替换比赛设施，核对换场布局、观众进出与席位遮挡。室内光源从顶棚和实际灯位组织，日间设定以实景采光为依据。

## 6. 灯光、材质和性能

- 有可靠赛事时间时，按经纬度、当地日期、当时的时区和真北计算白天太阳的高度角与方位角。夜间用赛道路面、维修区、看台或比赛场地主次分明的补光，重点照亮地标，保证环境还看得出层次。资料不足时保留示意说明。昼夜切换检查灯光状态、曝光、材质、天空和阴影。
- 先用场地和主要对象的局部亮度、对比与材质解决“夜里不突出”，再评估整体曝光。道路标线、护墙、台阶和轮廓可辨识，同时保留沥青、草地、混凝土、防滑铺装和金属的材质感。水面反光只布置在真实水域，与岸边光源位置相符。
- 采用程序纹理和已获许可的小图集，远近景保留合适的尺度和粗糙度。软阴影覆盖当前镜头附近。对斜视、贴地、远景、阴影覆盖边界与水面检查共面闪烁、闪变或重复纹理。
- 座椅、栏杆、人物、树木与设备优先使用实例化、合批和分级细节。按镜头距离控制车库、室内和座席细节出现，近景检验没有突兀消失。分场馆按需加载，控制纹理、阴影图、像素比、绘制调用、首屏下载与手机显存。按目标手机画质回退，同时保留点击、视角和地图功能。软件渲染可验证几何，手机性能以实际设备测量为准。

## 7. 接入现有项目与界面

- 为新增场馆独立维护场馆数据、模型、选座资料、场景配置、坐标投影和生成工具输出。按现有注册表和普通入口接入，优先复用现有材质、选座、维修楼、队伍与标签系统。新场馆差异用配置或专用模块表达；共享模块要验证旧场馆仍可正常使用。
- 在本仓库参考 `src/circuits/index.js`、`src/circuits/shanghai.js`、`src/circuits/singapore.js` 与 `src/venues.js`。看台与座位参考 `src/circuits/sg/stands.js` 和 `src/seatkit.js`，桥梁参考 `tools/sg-road-network.mjs`、`src/osm.js` 与 `src/circuits/sg/esplanade-bridge.js`，夜景参考 `src/circuits/sg/night-lighting.js`，维修区参考 `src/pitbuilding.js` 和 `src/circuits/sg/pitlane.js`。地图生成数据应可用已保留的原始数据与脚本重建。
- 保留中英文、桌面和手机竖屏、相机缩放与复位、看台列表、定位标签等已有入口。新增文案同步中英两个版本。交互与座位视角用实际鼠标或触摸操作复核，确认图标、地图、抽屉和按钮不互相挡住。
- 对上海与新加坡现有入口，指定赛道的查询参数优先，其次是浏览器记录。首次打开无参首页为上海，上海默认白天，新加坡默认夜晚。上海分享继续用首页地址，因而遵循收件人浏览器的赛道记录，新加坡的专属分享链接带 `?c=sg`。续做分享时检查复制链接、海报当前画面和二维码所指向的页面。场馆切换和引导动画要在真实入口验收，确认加载进度到达可交互画面。
- 如果本次涉及卫星图或外部加载，测正常、部分失败、全部失败和重试。只有覆盖内容可用时才报成功；失败时保留原场景和重试入口。模拟故障明确写成测试条件，实际线上发生频率另有证据时再报告。

## 8. 验收顺序与交付

按“资料和基线 → 全景位置与体量 → 局部模型 → 实测交互 → 本地预览与验收 → 按授权发布”的顺序。构建通过后继续检查真实浏览器画面。

| 验收项 | 要做的检查 | 完成时留下的证据 |
| --- | --- | --- |
| 资料与坐标 | 核对年份、真实尺度、路线方向、坐标投影、资料冲突与示意项 | 来源链接、目标场馆版本、尺寸表和精度说明 |
| 几何与穿模 | 全路网接头、桥底、桥墩、全部看台、屋盖与场地设施；逐类用实际模型验证 | 核查范围、测量值或扫描结果、异常点和处理结果 |
| 模型外观 | 全景、贴地、出口正对、过道侧视、桥底、两岸接头、地标正侧视和座位视角 | 关键问题前后同机位截图，昼夜各至少一次，截图注明区域与方向 |
| 功能入口 | 启动到可交互，场馆切换、相机复位、选择场馆、看台选座、分享与语言切换。按本次范围测正常和失败路径 | 浏览器操作结果、控制台和资源加载检查 |
| 兼容与性能 | 桌面和手机竖屏，普通使用入口与生产构建；共享逻辑变更后复测旧场馆 | 实测设备或视口、构建结果、可访问的本地链接 |
| 发布 | 查看最终差异，只暂存已确认范围。生成数据与构建产物复核；核对远端提交和部署 | 提交号、发布状态、线上入口和加载的对应版本 |

- 每次修复都明确记录“原问题 → 改动 → 验收结果”。截图能看清目标，避免只拍俯视、用阴影遮掩接缝或用含糊文字代替实测。检查结论要带覆盖范围。实际不可验证的部分写明证据缺口及影响范围，场馆或任务不涉及的验收项直接注明不适用。
- 资料或设计不确定时，可先做独立本地试版供比较，避免把尝试范围扩散到已验收模型。用户提供反例后，用同机位确认并检查关联位置。仅做审核时输出问题与证据，不执行修复。
- 按项目的正式入口运行和构建。此仓库通常用 `npm ci` 安装依赖，`npm run dev` 启动，`npm run build` 生成生产版，`npm run preview` 用于本地生产预览。重大视觉改动先提供本地预览，按当前指令推送经确认的版本。提交信息使用中文，暂存前查清已跟踪和未跟踪文件，排除其他草稿和临时下载文件。
- 涉及项目对外说明时同步中英文 README，维护在线入口、运行命令、数据来源、精度说明、素材许可和发布渠道。新项目或维护项目沿用指定渠道。本仓库发布走 GitHub 源码仓库和 Cloudflare Pages。部署后分别核对 GitHub 远端提交、Cloudflare 发布状态和生产站点实际引用的资源。出现延迟或失败时据实报告所在环节。
- 最终汇报包含已完成范围、关键资料、示意或待核实部分、验证方法与结果、预览地址和提交发布状态。有用户需要决定的事项只列具体缺失信息；例行验证和能安全修复的问题由你继续处理。
~~~
